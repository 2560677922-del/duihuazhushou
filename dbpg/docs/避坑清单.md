# 避坑清单

> 每条都是**真实踩过**的：现象 → 原因 → 解法。按主题分组，不按时间。
> 详细过程（含探针数据和截图）见 [`改动记录.md`](改动记录.md) 对应章节。

## A. 构建

**A1. `SDK location not found`**
`local.properties` 里的 `sdk.dir` 用了反斜杠。`.properties` 把 `\` 当转义符，`C:\Users` 会变成 `C:Users`。
→ 必须写正斜杠 `C:/Users/...`；`build-apk.cmd` 自动探测时已经处理。

**A2. `Unsupported class file major version` / `invalid target release`**
JDK / Gradle / AGP 三者版本没对齐。JDK 25 要求 Gradle ≥ 9.1；AGP 9.x 要求 Gradle 9.x。
→ 一起动，别只升一个。当前矩阵：AGP 9.4.1 / Gradle 9.8.0 / compileSdk 37 / JDK 25。

**A3. `Failed to find Build Tools revision`**
`compileSdk` / `buildToolsVersion` 与本机 SDK 里装的对不上。
→ 看 `Android SDK/platforms` 和 `build-tools` 实际版本再改。

**A4. APK 里是旧页面 / 引擎逻辑没更新**
`syncWeb` 读的是 `../dist`。
→ 先在 `duihuazhushou/` 跑 `npm run build`；或直接双击 `build-apk.cmd`（会先跑）。

**A5. `assets/www` 被手改后又被覆盖**
它是 `syncWeb` 的产物（`.gitignore` 里）。
→ 永远改 `../src` 或 `assets/msg`，别改 `assets/www`。

## B. Android UI

**B1. 列表一顿一顿**
以前每条消息一个 WebView，滚出屏幕回收、滚回来重新加载。
→ 列表里卡片走 `CardRenderer` 离屏位图 + LRU；WebView 只给可见富消息，回收池上限 2（`MAX_WEB_POOL`）。

**B2. 气泡能左右拖、每行字被切掉半边**
作者 CSS 写了固定宽度 / `nowrap`，WebView 把横拖当内容滚动。
→ 三道锁：`overflow-x:hidden !important`（guard + tailGuard）、`img/table/pre max-width:100%`、`onTouchEvent` 里检测到拖动就把事件交还父列表。

**B3. 文字比原生小一号**
`textZoom` 锁了 100，CSS px 恒等于 dp，不跟系统字体缩放。
→ `HtmlMessageView.cssOf(cfg, fontScale)` 用 `scaledDensity/density` 乘进字号。

**B4. 换主题后新出现的卡片还是白底**
`UiBackdrop` 一次性递归覆盖不到 RecyclerView 后来 inflate 的 item。
→ `hookRecycler()` 挂 `OnChildAttachStateChangeListener`，新项进场时按当前 token 补色。新列表页只要根布局有 RecyclerView 就自动生效。

**B5. 给没描边的 shape 硬加一圈框**
`GradientDrawable` 没有 `getStrokeWidth()`，无条件 `setStroke` 会给空描边加框。
→ 描边保留 XML 原值，只按需改色。

## C. WebView / iframe

**C1. 整页 HTML 被当代码块显示**
`marked` 遇到 `<html><head><style>` 会转义成源码。
→ 判定「整页文档」后走 `iframe srcdoc`，不交给 marked。

**C2. 卡片被撑出一串空行 / 出现 `<br><script>`**
`htmlifyNewlines` 在 `<head>`、`</div>` 之间插了 `<br>`。
→ `isFullHtmlDocument()` 为真时**不要**过 `htmlifyNewlines`。

**C3. 卡片永远缩不回去，底下留一大块空白**
高度探针用了 `documentElement.scrollHeight`，它至少等于视口高度。
→ 用 `body.scrollHeight / offsetHeight / getBoundingClientRect().height` 的最大值。

**C4. 卡片只有一条线 / 96px**
探针没回报（被系统挂起、`ResizeObserver` 不触发）。
→ 父壳 2.5 s 兜底按文档长度估高（上限 600px）；同时 `load/40/180/500/1200ms` 多次回报。

**C5. 别的 iframe 乱报高度，把这条卡片撑高**
`message` 事件没校验来源。
→ 只接受 `docFrames` 里 `contentWindow === e.source` 的那一个。

**C6. 卡片里的选项点了没反应**
`window.parent.document` 在 opaque origin 下抛 `SecurityError`，被作者的 `try/catch` 吞掉。
→ `sandbox` 必须带 `allow-same-origin`；`#send_textarea` / `#send_but` 必须真实存在（不能 `display:none`，会让 `focus/setSelectionRange` 失败）。

**C7. `SillyTavern is not defined`**
卡片脚本在 `<body>`，shim 注入在 `</body>` 前 —— 太晚。
→ `HOST_SHIM` 插在 `</head>` 之前（或文档最前面）。

**C8. 卡片里的 `<script src="https://…">` 不执行**
`allow-scripts` 有，但 CSP / 网络权限。
→ WebView 允许网络加载（`blockNetworkLoads=false`）；远程脚本能否加载取决于对方 CORS，不保证。

**C9. 点链接把整个气泡跳走**
→ `render.js` 统一给 `<a>` 加 `target=_blank` + `rel=noopener`；`WebViewClient.shouldOverrideUrlLoading` 拦下交系统浏览器。

## D. 正则语义

**D1. `<options>` 被删、卡片没选项**
`[12]` 是 `markdownOnly + promptOnly` 双 true，旧判定 `promptOnly && !markdownOnly` 没跳过它。
→ 显示侧 `if (promptOnly) continue`。详见 `预设兼容性.md` §2.1。

**D2. `$0` 不生效 / 只剩 `$0` 字面量**
Java/Kotlin 的字符串替换把 `$0` 当组引用；JS 里 `$0` 是字面量、`{{match}}` 才是整段。
→ 先把 `{{match}}` 换成 `$0`，再用 lambda 重载替换。

**D3. `trimStrings` 去错地方**
ST 是按「被引用的分组内容」去字，不是整个匹配。
→ 在 `$n` 展开时对每个值单独 trim，最后不要对整段再 trim 一次。

**D4. 正则编译失败，整条脚本静默失效**
变长后顾（`(?<=a*)`）在 Java 里不支持。
→ `RegexUtil.relaxLookbehind` 把 `*→{0,512}`、`+→{1,512}` 兜底；失败会在 logcat 打 `[正则] 脚本「…」编译失败`。

**D5. 正则匹配不到 `---`**
`htmlifyNewlines` 把 `\n` 变 `<br>`，`---` 又被 marked 渲染成 `<hr>`。
→ 任何按行/分隔线定位的逻辑，先做**等长归一化**（把 `<br>`、`<hr>` 换回等长占位再扫）。

**D6. 深度限制把最新消息排除了**
`maxDepth=1` 意味着只看最新 1 条；`depth` 从 0 开始。
→ 显示侧逐条传 `depthOverride`，别一律传 0。

**D7. 变量宏把随机宏吃掉**
先跑 `applyMacros`（未知清空）再跑 `readVariables`，`{{random::}}` 就没了。
→ 显示侧用 `expandMacrosForDisplay`（未知保留）；顺序：正则 → 宏 → 变量。

## E. 预设与插件

**E1. 插件「已启用但没效果」**
`claim` 判据太宽（「有 HTML 就认领」），被思维链折叠栏抢先。
→ 认领只认「未硬化的整页/片段文档」，并对已承载面板数据的卡片放行。

**E2. 只有一条横线**
把 `---` 当硬前提，但真机 rich 里已经是 `<hr>`。
→ 别在渲染层猜结构；先看 hits 和探针。

**E3. 正文被塞进面板**
用「最后一条 `---` 之后」定位，分隔线常落在正文中间。
→ 这类「从散文猜语义」的适配**全部删除**。模型没吐标签就是没遵守预设，重生成即可。

**E4. 插件升级后老用户状态丢了**
改了 id，`installed` 集合里还是旧 id。
→ `PluginStore.migrateLegacy()`：旧 id 映射到新 id，保留启用态。

**E5. 想给插件加「删除」**
库会丢。
→ 只做 `uninstall`（移出 installed），`PluginCatalog.ALL` 永远在代码里。

**E6. 插件输出在缓存里被二次改写**
把插件产出写回了 `RenderCache`。
→ 缓存只存原始 `rich`；`decideRender` 每次命中重跑插件。

## F. 数据与缓存

**F1. 改了设置，旧消息不更新**
缓存键少了维度。
→ `RenderKey(contentHash, cfgHash, lookHash, depth)`，少一个就会出现「改了没反应」。

**F2. 图片删了，气泡里还留着旧缩略图**
LRU 缓存命中了已删除文件。
→ 渲染时过滤 `File.exists()`；查看器删图后把消息里的引用一并摘掉。

**F3. 同一会话两次写交叉，文件损坏**
多线程写整文件。
→ `SessionRepo` 单线程池 + 原子替换 + fsync。

**F4. Activity 销毁后 WebView 泄漏**
WebView 持有 Activity context，回收池不负责销毁。
→ `HtmlMessageView.releaseAll()` 在 `onDestroy` 统一 `destroy()`。

**F5. 生成回调打到已销毁的界面**
直接持有 Activity 引用。
→ `GenBridge` 按 `requestId` 查 `Sink`，`release()` 后回调丢弃。

## G. 调试方法（比猜快十倍）

**G1. 先看形态，再看语义**
App 内：设置 → 渲染与上下文 → 渲染自检（输入形态 / rich 长度 / 开头 160 字 / 各插件认领 / 产出长度）。

**G2. 结构探针**
插件设置页 → 结构探针：卡片后正文 N 行 / 选项行 M / 分隔线 K。全是 0 = 正则没命中。

**G3. 复制完整 rich**
自检页可以直接复制跑完正则的 rich，贴进实验台的 `render.html` 复现，不用反复装机。

**G4. `chrome://inspect`**
`MainActivity` 开了 `setWebContentsDebuggingEnabled(true)`，电脑连手机可看消息 WebView 的 console。

`/workspace/st-lab` 里用 Playwright 加载**真的** `render.html` 和**真的**预设正则，点按钮、量高度、截图。改一轮几秒钟。
详见 [`验证与实验台.md`](验证与实验台.md)。

## H. 方法论（最贵的几条）

**H1. 不要在渲染层给预设打补丁**
「从散文里猜面板」写了 400 行，最后证明模型只是没按格式输出。渲染层只做形态归一。

**H2. 不要相信「看起来像」的中间产物**
`rich` 里的 `<br>`、`<hr>` 会让所有按行文本的假设失效。定位问题要打印真实字节。

**H3. 一个判据只回答一个问题**
`claim` 既判围栏又判正文、既判结构又判语义，必然误伤。拆成多个独立判据。

**H4. 每次只改一处，改完立刻用真数据验**
同时改「认领 + 模板 + 折叠」，出问题时无法归因，只能回滚重来。

**H5. 用户的「感觉」通常指向真问题，但归因可能错**
「预设失效」→ 实际是正则双标志；「只有一条横线」→ 实际是围栏配对。先复现，再归因。
