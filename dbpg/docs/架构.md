## 1. 三层，三条边界

```
┌─────────────────────────────────────────────────────────┐
│ 原生 UI（app/）                                          │
│  Activity / Adapter / Controller / SharedPreferences     │
└───────────────┬─────────────────────────────┬───────────┘
                │ JSON（DisplayConfig / 会话）│ evaluateJavascript
┌───────────────▼──────────────┐   ┌──────────▼───────────┐
│ 显示引擎（stcore/，纯 Kotlin）│   │ 生成引擎（../src）    │
│ 正则 / 宏 / 变量 / 分块       │   │ 提示词 / 资产 / 请求  │
└──────────────────────────────┘   └──────────────────────┘
```

| 边界 | 规则 |
| --- | --- |
| 原生 ↔ stcore | stcore **不能** import `android.*`。它的输入输出都是 data class / String，所以能跑 JVM 单测 |
| 原生 ↔ 生成引擎 | 只走 `GenBridge.request()` + `NativeBridge.onGenDelta/onGenDone`，参数全是 JSON 字符串 |
| 生成引擎 ↔ 显示 | **不直接通信**。生成引擎只负责产出文本；显示侧按快照重算 |

> 为什么不让生成引擎顺手把 HTML 渲染好？因为它的产物要落库（原文），而显示要随外观/预设变化重算。两件事混在一起，就会出现「改了字号旧消息不更新」。

## 2. 一次生成的时序

```
NativeChatActivity.submitInput()
  └─ ChatController.send(text)
       ├─ SessionEditor.appendAction(doc, …) → SessionRepo.save()   // 原文落库
       └─ beginGen(actionId, text)
            ├─ SessionHistory.export()       // 摘要替换 + 裁剪
            └─ GenBridge.request(sessionId, messages, userInput,
                                 assetBinding, presetId)
                 └─ EngineBridge.evaluate("__dhpApi.generate(...)")
                      └─ web 引擎：预设 → 提示词 → 请求
                           ├─ NativeBridge.onGenDelta(requestId, full)
                           ├─ NativeBridge.onGenDone(requestId, full)
                           └─ NativeBridge.onGenError(requestId, msg)

NativeBridge（Java，JS 线程）
  └─ GenBridge.dispatch(requestId, …)          // 按 requestId 找回 Sink
       └─ main.post { sink.onGenDelta(full) }  // 统一切主线程
            └─ ChatAdapter.patchStreaming()    // 只 rebind 这一条
```

**为什么要有 `requestId`**：Activity 会被重建，Sink 注册在全局表里，回调到达时按 id 找；找不到就丢弃。直接让 JS 调某个 Activity 实例，迟早泄漏。

**停止生成**：`GenBridge.stop(requestId)` → web 引擎 abort → `onGenStopped(partial)`，部分内容仍落库（用户能看到「停在哪」）。

## 3. 显示链路（每个函数为什么存在）

入口：`stcore/ImageMarker.kt` 的 `transformForDisplayRich(text, attachments, scripts, vars, ctx, …)`

```
raw
 ├─ ① cleanOutput(raw, cutMarker)                        hideReasoning 时剥思维链
 ├─ ② runRegex(forDisplay = true)                        显示正则
 │     ├─ RawScript from DisplayConfig.scripts           web 引擎下发的快照
 │     ├─ 逐个脚本：disabled / placement / 深度 / 双标志
 │     └─ buildReplacement：$0 → {{match}}、$n、$<name>、trimStrings、宏
 ├─ ③ expandMacrosForDisplay()                           宏（未知保留）
 ├─ ④ readVariables()                                    {{getvar}} 等，写宏抹空
 ├─ ⑤ stripImageMarkers()                                <img>/标记 → 图片块
 └─ ⑥ 分流
       ├─ isFullHtmlDocument ? 原样 : htmlifyNewlines
       └─ DisplayResult(blocks = stripHtmlNoise(rich), html = rich)
```

### 3.1 为什么 ③ 不能省

正则的替换串里虽然有宏展开（`buildReplacement`），但那只覆盖 `$1` 引用的内容。预设卡片是「整份 HTML + JS」，文案写在 HTML 里（`{{random::…}}`、`{{time}}`），不跑 ③ 就会把花括号漏到气泡里。

显示侧用 `expandMacrosForDisplay`（未知宏**原样保留**），组装提示词才用 `applyMacros`（未知清空）。两者共用实现，只差一个 `keepUnknown`。

### 3.2 为什么 ⑥ 要区分整页

- `htmlifyNewlines` 把 `\n` → `<br>`，这是角色扮演分段必需的（HTML 会把换行折叠成空格）。
- 但整页文档（`<!DOCTYPE html>` / `<html>` / `<head>`）自带排版，插 `<br>` 会在标签之间撑出空行，卡片变成一长条。
- 所以 `isFullHtmlDocument()` 为真时原样交给 WebView，否则才转 `<br>`。

### 3.3 纯文本兜底

`stripHtmlNoise(rich)`：删 `script/style` → 块级标签换行 → 剥行内标签 → 解实体 → 丢装饰行（`**`、`---`、`~~`）→ 压空行。

它不是「主渲染」，只是给这三处用：无障碍、复制、以及 `web == null` 时的 TextView 兜底。**不要**拿它当卡片渲染的降级方案 —— 卡片一旦有 HTML 就必须走 WebView。

## 4. 渲染决策（`ChatController.decideRender`）

```
rich（跑完正则/宏/变量的富文本）
  │
  ├─ PluginRegistry.resolveHtml(rich, meta)        有插件认领 → pluginHtml
  ├─ effective = pluginHtml ?: rich
  ├─ cleaned = HtmlSanitizer.clean(effective, allowScript)
  ├─ web = cleaned 非空 && htmlRender && hasMarkup(cleaned) ? cleaned : null
  ├─ fold = web == null && FoldParser.hasFold(rich) ? rich : null
  └─ RenderedMsg(plain, paths, rich, web, fold)
```

- `hasMarkup`：任意非 `<br>` 的开/自闭合标签。**不列白名单** —— 作者自定义标签（`<xy-card>`）也要走 WebView，宁可多一次渲染，也不要显示成裸字。
- `web == null && fold != null`：用户关了富渲染，但消息是 `<details>` → 原生折叠块至少能看。
- 三条路径互斥：卡片（`web`）> 折叠块（`fold`）> 纯文本。

### 4.1 缓存

`RenderCache` 的 key = `RenderKey(actionId, contentHash, cfgHash, lookHash, depth)`。

| 字段 | 什么时候变 |
| --- | --- |
| `contentHash` | 消息文本 / 图片引用变化 |
| `cfgHash` | 预设、正则组、世界书、变量版本变化 |
| `lookHash` | 外观（字号/行距/字体/颜色/气泡宽度）变化 |
| `depth` | 只有存在 `minDepth/maxDepth` 脚本时才参与（`depthSensitive`） |

**插件输出不写回缓存**：缓存里永远存原始 `rich`，`decideRender` 每次命中都重跑。否则插件改写一次、下次命中再改一次，会叠加。

## 5. 消息 WebView 与 iframe

### 5.1 壳（`assets/msg/render.html`）

每个 `HtmlMessageView` 只在创建时加载一次这个壳，之后用 `evaluateJavascript("DHP.render(...)")` 换内容。不重建文档、不重建 JS 上下文。

壳里同时放着**宿主兼容层的 DOM**：

```html
<textarea id="send_textarea" readonly></textarea>   <!-- 预设脚本找的"酒馆输入框" -->
<button id="send_but"></button>                     <!-- 预设脚本找的"发送键" -->
```

两个元素挪到可视区外（`left:-10000px`）而不是 `display:none` —— 后者会让 `focus()` / `setSelectionRange()` 失效，脚本半路抛错。

### 5.2 整页卡片（`render.js` 的 `makeDocFrame`）

```
srcdoc = 原文档
  + <head> 里补 viewport（作者没写时）
  + <head> 末尾插 HOST_SHIM（window.SillyTavern，必须早于卡片脚本）
  + guard 样式（overflow-x:hidden / max-width:100% / body 透明）
  + </body> 前插 PROBE（高度探针）+ tailGuard
```

- `sandbox="allow-scripts allow-same-origin"`：前者是卡片脚本必需，后者是 `parent.document` 必需。代价：卡片能摸到本壳 DOM 和 `DHPBridge`；桥只暴露 `height / input / send / getSettings / saveSettings`，`allowFileAccessFromFileURLs=false`，风险限制在一条气泡内。
- 高度：`PROBE` 用 `body.scrollHeight`（不是 `documentElement.scrollHeight`，后者永远不小于视口，折叠后缩不回去），`ResizeObserver` + 多次 `setTimeout` 兜底，`postMessage({__dhpH})` 回父壳。父壳只接受 **自己 iframe 的 source**，防止别的卡片乱报。
- 首帧占位 96px；2.5 s 内没回报就按文档长度估一个上限 600px，避免卡片被裁成一条线。

### 5.3 卡片点选项的完整通路

```
卡片按钮 onclick
  └─ window.parent.document.getElementById('send_textarea').value = 'A. …'
     window.parent.document.getElementById('send_but').click()
        └─ HOST_SHIM 捕获 click → bridge.send(text)      [iframe 内 shim]
           └─ parent.DHPBridge.send(text)                [同源]
              └─ HtmlMessageView.Bridge.send()           [JS 线程]
                 └─ main.post { hostListener.onSend() }  [主线程]
                    └─ ChatAdapter.Listener.onMessageSend()
                       └─ NativeChatActivity → 生成中挡住 / 空闲则 submitInput()
```

「填入 / 追加」模式不调 `generate()`，只写 textarea 并 dispatch `input`，由 `render.js` 监听后转成 `DHPBridge.input()`，原生把字填进输入框。

`extensionSettings` 存在 `SharedPreferences("dhp_host")`，所以卡片自己的「直接发送 / 仅填入 / 追加」开关是持久的、跨气泡的。

## 6. 插件契约

### 6.1 接口（`chat/render/plugin/RenderPlugin.kt`）

```kotlin
interface RenderPlugin {
    val descriptor: PluginDescriptor      // id / name / version / apiVersion / priority / scope
    fun claim(rich: String, meta: PluginRenderMeta): Boolean
    fun render(rich: String, meta: PluginRenderMeta): String
    fun onActivate(ctx: Context) {}
}
```

- `claim` 必须**快**且有明确判据；不许「消息里有 HTML 就整条认领」（思维链折叠栏也是 HTML，会被误伤）。
- `render` 只做形态归一：**不解析语义、不填模板、不猜选项**。
- `PluginRenderMeta`：`messageId / depth / presetId / sessionId / readAsset`。

### 6.2 生命周期（`PluginStore`）

| 操作 | 语义 |
| --- | --- |
| `install(id)` | 写 `installed` 集合 + `enabled` 集合 |
| `uninstall(id)` | 只从 `installed` 移除；**内置插件允许卸载，不允许删除** |
| `setEnabled(id, bool)` | 只动 `enabled` |
| `migrateLegacy(ctx)` | 老 id（`frontend_card_strict/loose`）→ `panel_data_adapter`，保留启用态 |

没有 `delete()`。库是代码内置的（`PluginCatalog.ALL`），卸载只是不加载 —— 这样「换预设就卸掉插件」随时可做，又不会把库弄丢。

### 6.3 仲裁（`PluginRegistry.resolveHtml`）

1. 取 `installed ∩ enabled ∩ apiVersion 匹配 ∩ scope.matches(presetId)`
2. 按 `priority` 降序
3. 逐个 `claim`，第一个认领的胜出（单 renderer）
4. 没有认领 → 返回 `null`（内置渲染原样工作，零插件时极快返回）
5. 全过程写 `RenderDiagnostic`：认领结果、失败原因、`probe`（卡片后正文 N 行 / 选项行 M / 分隔线 K）

### 6.4 当前唯一的插件

`FrontendCardPlugin`（`panel_data_adapter`，priority 120）：

- `claim`：围栏整页/片段未硬化，或裸文档 → 认领；已有面板数据的卡片放行
- `render`：`hardenDoc`（viewport / reset / vh / 横滚锁）+ `toDocument`（片段包文档）+ 围栏统一标 ` ```html `

它的存在理由是「WebView 需要一个完整文档才不跑版」，不是「生成面板」。

## 7. 存储布局

```
files/
├─ data/sessions/
│  ├─ index.json                 列表页只读这个（id / 标题 / 条数 / 时间 / 预览）
│  └─ <sessionId>.json            单个会话完整内容（actions / variants / summaries）
├─ data/…                        角色卡、世界书、预设缓存（由 web 引擎写，原生只读快照）
└─ files/Download/               <a download> 落盘
```

`SessionStore` 的设计取舍：**一个会话一个文件**。列表页不必解析几千条消息；写入是整文件覆盖 + fsync，所以必须单线程串行（`SessionRepo` 的 `dhp-session-io`）。

SharedPreferences：

| 名字 | 内容 |
| --- | --- |
| `dhp_appearance` | 外观（字号/字体/颜色/气泡/背景） |
| `dhp_render_plugins` | 插件安装 / 启用状态 |
| `dhp_summary` | 摘要开关、阈值、模型 |
| `dhp_host` | 卡片脚本的设置（`extensionSettings`） |
| 连接相关 | `settings/ConnectionStore`（baseUrl / key / model） |

## 8. 线程模型

| 位置 | 线程 | 规则 |
| --- | --- | --- |
| `SessionRepo` | 单线程池 `dhp-session-io` | 读写都丢进去，回调切主线程；单线程保证同会话两次写不交叉 |
| `GenBridge` | 回调在 JS 线程 → `main.post` | 所有 `Sink` 回调保证主线程 |
| `HtmlMessageView.Bridge` | JS 线程 | `height/input/send` 一律 `main.post`；`getSettings/saveSettings` 同步读写小 JSON |
| `CardRenderer` | 后台 | 离屏画 WebP，回调主线程 |

## 9. 快速定位表

| 症状 | 先看 |
| --- | --- |
| 卡片没出来 | `PluginRegistry` 诊断 → `claim` 是否为 false → `decideRender` 的 `hasMarkup` |
| 卡片出来了但缺内容 | `runRegex` 的 hits（哪条脚本 matches=0）→ 双标志 / 深度 |
| 选项点了没反应 | iframe `sandbox` 是否含 `allow-same-origin` → `HOST_SHIM` 是否注入 → `Bridge.send` |
| 气泡左右能拖 | `render.js` 的 guard + `HtmlMessageView.onTouchEvent` 的横滚交还 |
| 卡片高度不对 | `PROBE` 的 `body.scrollHeight` + 父壳 `message` 监听 |
| 改了设置旧消息不变 | `RenderKey` 的 `lookHash / cfgHash` |
| 生成卡住 / 串台 | `GenBridge` 的 `requestId` 映射 + `EngineBridge` 是否 ready |
| 正则编译失败 | logcat `[正则] 脚本「…」编译失败`，看 `RegexUtil.relaxLookbehind` 兜底 |
