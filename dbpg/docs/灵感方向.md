# 灵感方向

> **定位**：这不是清单库，是「动手前先看谁做过」的方向索引。核心原则只有一条：
> **任何新功能，先花 10 分钟找别人怎么实现的，再决定自己写多少。**
> 本项目最贵的一次返工（三轮「选项没渲染」）根因就是没先读 ST 源码、凭印象写判定——这一条比任何参考都值钱。

## 1. 第一优先：ST 官方（语义权威）

预设生态的一切行为定义都在这里，与它不一致时先怀疑自己。

| 去哪 | 看什么 |
| --- | --- |
| [官网文档](https://sillytavern.app) | 功能的用户视角说明（要做什么、为什么） |
| [源码](https://github.com/SillyTavern/SillyTavern)（AGPL-3.0） | `public/scripts/` 是显示、正则、宏、提示词顺序的全部语义来源 |
| 本地沙盒 `/workspace/st-lab/SillyTavern` | 已部署好，直接 grep 源码 + 起服务实测，不用去网上翻 |

**读法**：grep 功能名 → 只读「判定分支」（`if/else`、标志位组合），不读成功路径。我们在 `promptOnly` 双 true 上翻车，就是因为只看了文档没看分支。

## 2. 第二优先：第三方插件源码（手边就有）

高级预设的功能全靠插件实现，而且它们的解法已经过海量用户验证。

| 插件 | 在哪 | 学什么 |
| --- | --- | --- |
| 酒馆助手 JS-Slash-Runner | `/workspace/st-lab/plugins/JS-Slash-Runner` | **iframe 隔离 + API 注入**的整套做法：沙箱模型、宿主接口设计、消息楼层渲染、脚本生命周期。我们的渲染壳 + 宿主兼容层就是沿这条路走的 |
| 小白X LittleWhiteBox | `/workspace/st-lab/plugins/LittleWhiteBox` | 剧情总结/记忆包、变量与状态管理、应用面板（地图/钱包/游戏）——**做长篇扮演的原生功能时先来翻它** |
| [ST-Prompt-Template](https://github.com/zonde306/ST-Prompt-Template) | 需要时 clone | 提示词模板引擎（条件、循环、子模板），预设里的高级语法多半出自它 |

**读法**：看它的 `src` 结构和 API 面（它向脚本暴露了什么），功能思路直接对应我们的原生包；别抄它依赖浏览器 DOM 的部分。

## 3. 第三优先：同类开源客户端（原生功能找这里）

ST 本体没有移动端，把「Web 功能 → 原生实现」走过一遍的项目都在这：

| 项目 | 地址 | 与我们的关系 |
| --- | --- | --- |
| **TauriTavern** | [Darkatse/TauriTavern](https://github.com/Darkatse/TauriTavern)（AGPL） | **最像我们**：ST 前端 + Rust 原生后端（Clean Architecture 的 Cargo workspace），五端含 Android/iOS。移动端键盘避让、安全区、返回键分层、旧 WebView 兼容层踩坑都写在 `docs/AndroidDevelopment.md`——遇到原生 UI 问题先翻它 |
| **ChatterUI** | [Vali-98/ChatterUI](https://github.com/Vali-98/ChatterUI)（AGPL） | React Native 的 ST 风格客户端：角色卡 V2/V3 解析、会话管理、本地 GGUF 推理（`cui-llama.rn`）。做本地推理/卡片解析时看它的数据模型 |
| **RisuAI** | [kwaroran/Risuai](https://github.com/kwaroran/Risuai)（GPL） | 唯一活跃且有 Android 版的开源 BYOK 客户端，自研界面，看它的 UI 取舍 |
| Agnai / KoboldCpp | [agnaistic/agnai](https://github.com/agnaistic/agnai) 等 | 通用参考；KoboldCpp 是本地推理的事实标准后端 |

**注意**：TavernAI 2 是闭源二进制，没有可参考的源码，跳过。

## 4. 兜底：通用开源组件（别造轮子）

原生功能在 ST 生态找不到参考时，直接用成熟库，**凡是「通用能力」一律先搜现成库**：

| 要做 | 别手写 | 用什么 |
| --- | --- | --- |
| Markdown / 富文本 | 自己写解析器 | Android 端 Markwon；JS 端我们已用 marked |
| 代码高亮 | 自己写 lexer | highlight.js / prism |
| 向量检索（记忆/知识库） | 自己算余弦 | sqlite-vec、ObjectBox |
| 同步/备份 | 自己写协议 | WebDAV（ raging-loon / sardine-kt）、git-journal 式导出 |
| 本地推理 | 自己接 JNI | llama.cpp 官方 Android 构建 |
| TTS/语音 | 自己搞引擎 | 现成 TTS 服务/系统接口 |
| 表格/数据面板 | 自己拼 HTML | 第三方插件的实现（先回 §2 翻） |

## 5. 动手前的 30 秒检查

1. 这个功能 ST 官方有没有？（有 → 语义抄官方，判定分支逐条对）
2. 某个插件做过？（有 → 去 `st-lab` 翻源码，看它的接口设计）
3. 别的客户端做过？（有 → 看它怎么落到移动端/原生）
4. 都没有 → 搜通用库，最后才是自己写。
5. 抄**思路与契约**（怎么解析、怎么仲裁、怎么降级），不抄针对某个预设的补丁；注意 AGPL/GPL 许可的传染性——参考实现，不整段搬运代码。
