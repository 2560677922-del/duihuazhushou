# 验证与实验台

> 渲染层的问题**不能靠"装到手机上看看"**定位：一轮改代码 → 打包 → 安装 → 聊出卡片要几分钟，还受模型随机性影响。
> 这里的顺序是：**单测锁语义 → 实验台复现 → App 自检 → 真机只做最后确认**。

---

## 1. 单测

```bash
# 在 dbpg/ 下
./gradlew :stcore:test              # 218 个
./gradlew :app:testDebugUnitTest    # 14 个
./gradlew test                      # 全量
```

| 模块 | 覆盖 |
| --- | --- |
| `stcore` | 正则语义（`$0`/trimStrings/双标志/深度/substituteRegex）、宏、变量、思维链、图片标记、富文本、会话文档、摘要规划 |
| `app` | 插件契约（认领 / 产出 / 幂等）、渲染判定 |

**写测试的规矩**：

- 正则语义的测试要**贴真实预设片段**（例如 `[12]` 的 findRegex），不要自己编一个简化版 —— 坑都在细节里。
- 插件的测试只测**契约**（什么输入认领、输出的文档是否合法），不测某个预设的样式。
- 渲染结果不要断言整段 HTML（会天天变），断言结构：`contains("<html")`、`startsWith("```html")`、`!= 输入`。

## 2. App 内自检（不用连电脑）

**设置 → 渲染与上下文 → 渲染自检**

| 项 | 看什么 |
| --- | --- |
| 输入形态 | 纯文本 / 片段 / 整页文档（判定对不对） |
| rich 长度 | 0 = 正则没命中；暴涨 = 某条替换串炸了 |
| 开头 160 字 | 直接看跑完正则的文本长什么样 |
| 各插件认领 | 谁认领了、为什么没认领 |
| 生效插件 | 最终用哪个渲染器 |
| 产出长度 | 插件输出有没有被截断 |

**设置 → 插件 → 结构探针**

```
卡片后正文 N 行 / 选项行 M / 分隔线 K
```

三个都是 0 → 不是渲染问题，是正则没命中。M > 0 但卡片没按钮 → 才是面板模板/JS 的问题。

「复制完整 rich」把跑完正则的文本导出，可以直接喂给实验台。

## 3. 实验台（`/workspace/st-lab`）

不是仓库的一部分，是排查用的工作区。里面有三样东西：

| 目录 | 用途 |
| --- | --- |
| `SillyTavern/` | ST 源码（对照 `engine.js`、`script.js` 的语义） |
| `plugins/JS-Slash-Runner`、`plugins/LittleWhiteBox` | 第三方插件源码，参考它们怎么做卡片/交互 |
| `Meowssiah_1.9.12.json` | 真实预设，所有验证都用它 |
| `verify_*.js` | Playwright 脚本，直接跑 |

### 3.1 环境

```bash
cd /workspace/st-lab
npm i playwright-core        # 已装
# Chromium 用系统的 /usr/bin/chromium
```

脚本自己起一个静态 server 指向 `app/src/main/assets/msg`，所以**用的是 App 真正在用的** `render.html` / `render.js`，不是另写一份。

工程的默认路径是 `/tmp/duihuazhushou/dbpg`，换机器时用环境变量覆盖：

```bash
DBPG=/path/to/dbpg node verify_host.js
```

### 3.2 `verify_host.js` —— 卡片选项能不能点

```bash
node verify_host.js
```

流程：

1. 读真实预设，取 `[13] 前端综合面板` 的 `findRegex/replaceString`
2. 对一段模拟模型输出（4 个 `<options>` + `<comment>` + `<summary>`）跑替换，得到卡片 HTML
3. 起 http server，Playwright 打开 `render.html`
4. 注入假的 `DHPBridge`，记录 `input / send / settings` 调用
5. `DHP.render(card)` → 等 iframe → 点第一个选项
6. 断言：`SillyTavern` 是 object、`getContext` 存在、`#send_textarea` 可访问、收到 `input`/`send`

期望输出：

```
卡片长度: 32237
按钮: ["直接发送…","01A. 抱住她…","02B. …"]
SillyTavern: object getContext: true 输入框可见: true
命中选项: 01A. 抱住她，轻声安慰♥
--- 原生收到 ---
[["input","A. 抱住她，轻声安慰"],["send","A. 抱住她，轻声安慰"]]
PASS: 选项点击已到达宿主
```

### 3.3 `verify_file.js` —— `file://` 下的同源

App 里壳是 `file:///android_asset/msg/render.html`，`file://` 的 origin 是 opaque。这个脚本验证**在 file:// 下 `parent.document` 仍然可访问**（`canDoc: true`），否则真机上选项照样点不动。

```bash
node verify_file.js
```

### 3.4 `verify_modes.js` —— 发送 / 填入 / 追加

点卡片顶部的模式开关，确认：

- `saveSettingsDebounced` 把 `{"Astro":{"optionMode":"replace"}}` 回写宿主
- 「仅填入」模式下点选项**只发 `input`、不调 `send`**

### 3.5 加一个新验证脚本

复制 `verify_host.js` 改三处：

1. `PRESET` 路径 / 取哪条正则
2. `modelOutput`（模拟模型输出）
3. 断言（找按钮的选择器、期望的桥调用）

**别改 `render.html` 去适配脚本** —— 脚本要验证的就是 App 的真实产物。

## 4. 真机验证清单

装完 APK 按顺序过一遍，每项都能独立判断：

| # | 操作 | 通过标准 |
| --- | --- | --- |
| 1 | 导入预设 → 资产页看顺序 | 提示词顺序与预设一致，未激活项显示为灰 |
| 2 | 发一句，等回复 | 流式正常，结束后出现面板卡片（不是源码、不是一条线） |
| 3 | 看卡片内容 | 选项 N 个、悄悄话、小总结（`<details>`）都在 |
| 4 | 点一个选项 | 直接发出（默认模式），消息列表滚到底 |
| 5 | 点卡片顶部开关 → 「仅填入」→ 点选项 | 输入框出现选项文字，不自动发送 |
| 6 | 长按消息 → 重新生成 | 新回复替换，`‹ ›` 能翻回旧回答，**预设仍然生效** |
| 7 | 编辑一条旧消息 | 卡片按新内容重算（缓存失效） |
| 8 | 设置里改字号 / 字体 / 气泡宽度 | 旧卡片跟着变 |
| 9 | 设置 → 插件 → 卸载内置插件 | 卡片退化为纯文本/原始 HTML，**不崩**；重新安装后恢复 |
| 10 | 横拖卡片 | 页面不左右晃，文字不被切 |
| 11 | 折叠/展开 `<details>` | 卡片高度跟着变，下方正文不重叠 |
| 12 | 断开网络后打开旧会话 | 历史消息正常渲染（卡片不依赖网络，除非作者引了外链图） |

> 第 4、5 项依赖 `sandbox` 带 `allow-same-origin`。如果点了没反应，先看 `chrome://inspect` 里 iframe 的报错是不是 `SecurityError`。

## 5. 日志关键字

```bash
adb logcat | grep -E "DHP_HTML|\[正则\]|\[插件\]"
```

| 关键字 | 含义 |
| --- | --- |
| `[正则] 脚本「…」编译失败` | `findRegex` 语法问题，看后面的 pattern |
| `页面告警: …` | 卡片脚本自己 `console.warn` 的内容（经 `DHPBridge.warn`） |
| `插件安装状态迁移失败` | `migrateLegacy` 异常，不影响渲染 |
| `DHP_HTML` | WebView 生命周期 / 释放 |

## 6. 一次改动的标准流程

```
1. 复现：拿到一条真实模型输出 + 真实预设，写进实验台脚本
2. 归因：打印 rich / hits / claim，确认是"没命中"还是"渲染错"
3. 改一处：语义改 stcore，呈现改 render/，别同时动两层
4. 单测：给这次语义补一个用例（用真实预设片段）
5. 实验台：同一份输入，前后各跑一次，对比 PASS/FAIL
6. 打包：assembleDebug，解包确认资源进包（`unzip -p … | grep`）
7. 真机：只验这次改动涉及的那 1-2 项
8. 记录：docs/改动记录.md 追加「现象 → 真因 → 改法 → 数据」
```

第 6 步别省。曾经出现过「代码改了但 APK 里还是旧 `render.js`」——`syncWeb` / 资源合并的顺序问题，解包 `grep` 一下 10 秒。
