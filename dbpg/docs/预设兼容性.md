# 预设兼容性

> 目标：**导入 SillyTavern 预设即可用**，不为任何单个预设写适配。
> 本文是「我们支持什么、和 ST 哪里不一样、遇到新东西怎么加」的规范。

---

## 1. 支持的字段

### 1.1 正则脚本 `extensions.regex_scripts[]`

| 字段 | 支持 | 说明 |
| --- | --- | --- |
| `id / scriptName / disabled` | ✅ | 停用的脚本直接跳过 |
| `findRegex` | ✅ | `/pattern/flags` 形式；变长后顾自动降级（`*→{0,512}`） |
| `replaceString` | ✅ | `$0` = 整个匹配；`{{match}}` 同义；`$n`、`$<name>` |
| `trimStrings` | ✅ | 按**被引用的那段内容**去字（不是整段匹配） |
| `placement` | ✅ | `1` 用户输入 / `2` AI 输出 / `3` 斜杠 / `5` 世界书 / `6` 思维链；`0` 旧版「仅显示」 |
| `markdownOnly / promptOnly` | ✅ | 语义见 §2，**与 ST 刻意不同** |
| `substituteRegex` | ✅ | `0` 不替换 / `1` 原生宏 / `2` 转义后替换 |
| `minDepth / maxDepth` | ✅ | 距最新一条的深度；显示侧逐条传入 |
| `runOnEdit` | ✅（等价） | 我们每次渲染重算，编辑后自然重跑 |

**未实现**：`placement 4`（无对应消息类型）、`Overlay` 策略（ST 自己也没实现）。

### 1.2 宏

| 宏 | 说明 |
| --- | --- |
| `{{char}} {{user}} {{persona}}` | 角色 / 用户 / 人设名 |
| `{{description}} {{scenario}} {{mes_example}} {{original}}` | 角色卡字段 |
| `{{chat}} {{currentMessage}} {{lastMessage}}` | 上下文 |
| `{{getvar::x}} {{getglobalvar::x}}` | 读变量 |
| `{{setvar::x::v}} {{addvar}} {{incvar}} {{decvar}} {{deletevar}}` | 写变量（只在两个一次性入口执行） |
| `{{random::a,b,c}}` `{{random}}` | 随机（每次不同） |
| `{{pick::a,b,c}}` | 随机但**同文稳定**（滚动不换值） |
| `{{roll::1d6}}` `{{roll::2d6+1}}` | 骰点 |
| `{{time}} {{date}} {{weekday}} {{isotime}} {{isodate}}` | 本机时间 |
| `{{newline}} {{space}} {{trim}} {{noop}}` | 排版 |
| `{{// 任意内容}}` | 注释，整段删除 |
| `{{input}} {{lastUserMessage}} {{lastCharMessage}}` | 最近消息 |

**规则**：

- 显示侧：未知宏**保留原文**（`expandMacrosForDisplay`）
- 提示词侧：未知宏**清空**（`applyMacros`）—— 别把 `{{foo}}` 发给模型

### 1.3 预设结构

| 字段 | 支持 |
| --- | --- |
| `prompts[]` | ✅ 提示词库（含 `enabled`、`role`、`content`、`injection_position`） |
| `prompt_order[<character_id>].order[]` | ✅ 顺序 + 未激活项；`100000`（角色）/ `100001`（主提示）分组 |
| `extensions.regex_scripts` | ✅ |
| `extensions.tavern_helper.variables` | ✅ 初值导入 |
| `assistant_prefill` / `wi_format` 等采样参数 | ✅（由 web 引擎消费） |
| `extensions.SPreset.*` | ❌ 见 §3 |

### 1.4 变量

`session` / `global` 两张平级表，单次替换、不嵌套。

- 写宏只在「用户发送」「AI 回复落库」两个入口执行（`applyVariableWrites`）
- 只读路径（渲染 / 提示词）里的写宏被抹成空串，**不改表**
- `{{getvar::{{char}}}}` 这种嵌套不支持（正則是 `[^{}]`）

## 2. 和 ST 刻意不同的两处

### 2.1 「双 true」的脚本：分侧处理

ST 的 `getRegexedString`（`public/scripts/extensions/regex/engine.js`）是**或**关系：

```js
if ((script.markdownOnly && isMarkdown) ||
    (script.promptOnly && isPrompt) ||
    (!script.markdownOnly && !script.promptOnly && !isMarkdown && !isPrompt)) {
    // 执行
}
```

所以双 true 的脚本在 ST 里**显示和提示词两侧都跑**。

真实预若不是这么用的。Meowssiah 的 `[12] 行动选项2`：

```json
{ "markdownOnly": true, "promptOnly": true,
  "findRegex": "/(<options>[\\s\\S]*?<\\/options>)/g", "replaceString": "" }
```

- ST 语义：显示时先删掉 `<options>`，后一条 `[13] 前端综合面板` 再也匹配不到选项 → **卡片里永远没有按钮**
- Tavo 语义：显示侧跳过 `promptOnly` → 选项保留，`[13]` 正常出卡片

我们的选择：

| 场景 | 判定 | 理由 |
| --- | --- | --- |
| 显示 | `promptOnly` 一律跳过 | 与 Tavo 实测一致，保住 `<options>` |
| 提示词 | 跳过 `markdownOnly && !promptOnly` | 双 true 照跑 —— 作者写 `promptOnly` 就是想让它在进模型前消失 |

**别照 ST 源码改回去**。`RegexEngine.kt` 里的注释和单测（`双 true 脚本 显示跳过 提示词执行`）就是防这个的。

### 2.2 「双 false」的脚本：两边都跑

ST 把双 false 的脚本当作「落库时改写一次」，写进聊天记录的已经是改写后的文本，之后显示不再跑。

我们**落库存原文**，每次渲染重算，所以显示和提示词两侧都必须跑 —— 否则普通美化正则永远不生效。

这是存储模型的差异，不是语义分歧。改存储模型（改成存改写结果）会连带失去「换预设即换渲染」的能力，不建议。

## 3. 已知边界

| 项 | 现状 | 影响面 |
| --- | --- | --- |
| `extensions.SPreset`（MacroNest / MessageInjections / FinalRequestProcessing / ChatSquash） | 不执行 | 提示词层的增强；显示不受影响 |
| `extensions.tavern_helper.scripts` | 不执行（网页端注入脚本） | 依赖它初始化数据的卡片会缺料 |
| 世界书条目自带正则（Tavo 扩展） | 只做世界书注入，不跑条目级正则 | ST 标准里没有这个字段 |
| Quick Replies / `triggerSlash('/send …')` | 未映射 | 少数用斜杠命令而非 `getContext()` 的卡片 |
| 流式输出 | 期间显示原文，结束才出卡片 | 与 ST 一致（流式不渲染 markdown） |
| 变量嵌套 | 不支持 | 极少数写法 |
| 卡片 `fetch` 外部 API 存档 | 能发请求，但没有 ST 的 `/api/*` 后端 | 依赖服务端的卡片会降级 |
| `placement 4` | 无对应消息类型 | 极少使用 |

## 4. 遇到新预设，按这个顺序查

1. **先看它产出什么形态**
   模型输出里有没有 `<options>` / `<summary>` / 自定义标签 / 整页 HTML？把一条真实回复贴进「渲染自检」，看 rich 长度和开头 160 字。

2. **再看正则命中没有**
   插件设置页的「结构探针」：卡片后正文 N 行 / 选项行 M / 分隔线 K。若全是 0，说明正则没命中，不是渲染问题。

3. **逐条看 hits**
   `RegexEngine` 的 `RegexHit` 有 `matchCount` 和 `sample`（前后 24 字上下文）。`matches=0` 的脚本，检查：
   - `disabled` 是不是 true（预设里本来就关着）
   - `placement` 是否包含 `2`
   - `minDepth/maxDepth` 是否把这条消息排除了
   - `markdownOnly/promptOnly` 是否被我们的分侧规则跳过

4. **最后才怀疑渲染**
   卡片有了但样式不对 → 看 iframe 是否 `allow-scripts`、`<head>` 是否被补了 viewport、作者 CSS 是否依赖了 `:root` 变量。

> 经验：**九成的「预设失效」是正则没命中或开关没开，不是渲染器的问题。** 上一轮 400 行「散文猜面板」就是跳过了第 2、3 步直接改渲染，最后全删。

## 5. 加一个新能力，检查清单

1. **它属于哪一层？**
   - 语义（正则/宏/变量）→ `stcore`
   - 呈现（HTML/卡片/高度）→ `app/chat/render`
   - 提示词 → `../src`
2. **会不会破坏「落库存原文」？** 会的话重新设计。
3. **是不是只对某个预设有效？** 是的话不做，改成按形态/契约判断。
4. **停用后能不能回到原始文本？** 不能的话说明耦合了。
5. **补单测**：
   - 正则语义 → `stcore` 单测（带真实预设片段）
   - 插件 → `PluginCatalogTest`（只测契约：认领/产出，不测某个预设的样式）
6. **补文档**：在 `docs/改动记录.md` 追加一节，写清「现象 → 真因 → 改法 → 验证数据」。
