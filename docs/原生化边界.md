# 原生化边界（哪些必须过桥，哪些已经原生）

> 原则（2026-11-07 与用户确认）：
> **能不用桥就不用桥**。桥只保留"为了兼容 SillyTavern 格式"的服务端逻辑，
> 因为那套解析/拼装逻辑在 web 引擎里已经跑通、且必须与 ST 行为逐位一致。
> 其余一律原生实现。

## 二、走桥的（因为必须与 ST 行为一致）

| 桥方法 | 用途 | 为什么不能马上原生 |
|---|---|---|
| `getAssets` | 预设/世界书（含条目）/正则 清单 | 数据由 web 的 assets store 解析、归一化（ST 各种历史格式） |
| `command wbSaveEntry / preset*` | 条目/子条目增删改 | 同上，字段语义（蓝灯/选择性/位置/深度）由引擎定 |
| `setAssets` | 启用/停用预设、世界书、正则 | 选择集语义与 ST 一致 |
| `importAsset / exportAsset` | ST .json 导入导出 | `importAnyJson` 统一识别（数组混装/容器/entries 索引） |
| `getConfig / llmAddProvider` | LLM 运营商与模型 | 生成请求由引擎组装并发出，配置必须同源 |
| `getImageConfig / getImageStyle / img*` | 生图运营商/风格/采样/上文条数 | 与自动配图共用同一份 store，避免两处分叉 |
| `getDisplaySettings / saveDisplay` | 隐藏思维链 / 发给后端带不带正则 | 影响发给模型的上下文，属于引擎行为 |
| `optimizeImagePrompt` | 对话生图用 LLM 转标签 | 复用引擎的流式对话客户端与鉴权 |
| `generate / stop`（`__dhpGen`） | 聊天生成 | 提示词组装（预设/世界书/正则/宏）在引擎里 |
| `__dhpData` 迁移 | 一次性网页数据迁移 | 只跑一次，迁移完即可不再用 |

## 三、下一步原生化的候选（按收益排序）

1. **提示词组装**移到 stcore：`assemblePrompt` 已有清晰的输入输出，配一组
   与 web 相同的测试向量（同输入 → 同 prompt 字符串）就能安全替换；
   替换后生成链路只剩"HTTP 流式请求"，可以彻底原生（stcore 已有 OkHttp）。
2. **资产存储**原生化：worldbook/preset/regex 的 JSON 直接用 Kotlin 读写，
   桥只保留"导入解析"这一件事（ST 格式兼容入口）。
3. **变量表**：stcore 已有变量引擎，把会话变量落盘原生化。

## 四、渲染策略说明（为什么用内嵌 WebView）

同类产品（如 Tavo）也是「原生外壳 + 消息 HTML 由 WebView 渲染」，因为它能：
- 真正吃下美化正则产出的 `<style>`/`<div>`/`flex`/渐变，而不是把 CSS 当正文；
- 保留 ST 社区美化卡的视觉一致性（web 端打磨过的效果直接复用）。

我们的实现细节：
- 只有"像 HTML"的消息（含 `<style>` 或 ≥2 个块级标签）才走 WebView，
  普通 Markdown/纯文本仍用 TextView（快、可选中复制）；
- 每气泡独立 WebView，禁文件访问/禁跨域跳转/禁 DOM 存储；
- **脚本默认剥离**（`<script>` 与 `on*` 属性），设置里可显式打开；
- 高度按 `scrollHeight × density` 二次测量，长消息不会被截断。
