## 二、生图模块（重点：ZIP 识别与解压）

### 2.1 能力
- 纯 Kotlin 原生网络（OkHttp），**不受 CORS 限制**，可连局域网 / 本地电脑模型（`http://192.168.x.x:port`）。
- 长超时：连接 30s、读 300s、整体调用 360s。
- 兼容各种第三方中转站返回格式（zip / 图片 / JSON / dataURL / 纯 base64）。
- 落盘到 App 私有目录，返回**路径 + Uri**，不返回 base64。

### 2.2 纯逻辑接口（`com.dbpg.stcore.imagegen`）

```kotlin
// 响应解析总入口
ImagePayloadExtractor.extract(contentType: String?, body: ByteArray): Result

data class Result(
    val kind: String,                 // empty/zip/image/json/json-url/dataurl/base64/text/unknown
    val images: List<Source>,         // 已解析出的图片
    val rawText: String? = null,      // 非图片文本（用于把中转站报错回显给用户）
)
sealed class Source {
    data class Inline(val bytes: ByteArray, val mime: String, val origin: String) : Source() // 已拿到字节
    data class Remote(val url: String) : Source()                                             // 只拿到地址
}

// 辅助

Base64Codec.decode(input: String): ByteArray                 // 自研，兼容 minSdk24（不用 API26 的 java.util.Base64）
Base64Codec.isLikelyBase64(input: String, minLen: Int): Boolean

ImageFormat.isImage(mime: String?): Boolean

ImageRequestBuilder.buildOpenAiJson(model, prompt, size, n, responseFormat, quality, style, extra): String
ImageRequestBuilder.buildHeaders(apiKey, extra): Map<String, String>
```

### 2.3 ✅ ZIP 是怎么被识别并解压的（核心）

**结论：以「文件头 magic bytes」为准，不轻信 Content-Type。**

很多中转站会把 ZIP 包的 `Content-Type` 写成 `application/json` 或 `application/octet-stream`，
如果只看响应头就会误判成 JSON 去解析，直接失败。所以判定顺序是：

1. **先看字节**（`ImagePayloadExtractor.isZip`）：
   - `50 4B 03 04` → 普通 ZIP
   - `50 4B 05 06` → 空 ZIP
   - `50 4B 07 08` → 分卷 ZIP
   命中即判定为 ZIP。
2. 再看 `Content-Type` 是否含 `zip` / `x-compressed` / `x-zip`（辅助判断）。
3. 判定为 ZIP 后，**全程在内存里解压**（不落临时文件）：
   ```kotlin
   ZipInputStream(ByteArrayInputStream(body)).use { zis ->
       var entry = zis.nextEntry
       while (entry != null) {
           if (!entry.isDirectory) {
               val data = readLimited(zis, MAX_ENTRY_BYTES)      // 单文件上限 40MB
               val mime = sniffMime(data) ?: mimeFromName(entry.name)
               if (mime != null) out.add(Source.Inline(data, mime, "zip:${entry.name}"))
           }
           zis.closeEntry(); entry = zis.nextEntry
       }
   }
   ```
   - **每个条目也按文件头认图片**，认不出再按扩展名兜底；只收图片条目（`readme.txt` 之类自动跳过）。
   - **防 ZIP 炸弹**：单条目 ≤ 40MB、解压总量 ≤ 128MB，超限条目直接丢弃。
   - ZIP 损坏：不抛异常，返回已成功读到的图片（宁可能用多少用多少）。
4. 如果 ZIP 里一张图都没有，才继续往下走（按图片 / JSON / dataURL / base64 解析）。

### 2.4 其它返回格式的兜底顺序
1. ZIP（见上）
2. 直接是图片字节（`sniffMime` 命中）
3. 文本：
   - `data:image/...;base64,...` → 解码
   - `{...}` / `[...]` JSON → 递归挖 `b64_json` / `url` / `image` / `images` 等
   - 纯 base64 文本 → 解码后必须是图片文件头才认
   - 都不是 → `kind="text"`，把 `rawText` 回显（中转站的报错信息）
4. JSON 里给的是 `url` → 返回 `Source.Remote`，由上层再下载一次

> JSON 里既可能给 base64 也可能给 url：优先取 base64（省一次下载）；只有全是 url 时才走下载。

### 2.5 Android 胶水（`com.dbpg.duihuazhushou.imagegen`）

```kotlin
// 网络层：只发请求拿原始字节
class HttpImageClient {
    data class RawResponse(val code: Int, val contentType: String?, val body: ByteArray)
    fun postJson(url: String, headers: Map<String,String>, json: String): RawResponse
    fun getBytes(url: String): RawResponse

class ImageStore(context: Context) {

    fun save(bytes: ByteArray, mime: String): StoredImage?
```

## 三、富文本渲染模块

### 3.1 纯逻辑（`com.dbpg.stcore.richtext`）
把「网页正则处理后可能带简单格式的文本」解析成**纯数据**（纯文本 + 样式区间），与 Android 解耦。

```kotlin
RichTextParser.parse(raw: String): RichText
data class RichText(val plain: String, val spans: List<RichSpan>)
data class RichSpan(val start: Int, val end: Int, val style: RichStyle, val url: String? = null)
enum class RichStyle { BOLD, ITALIC, CODE, STRIKE, LINK }
```
支持：`**粗体**`、`*斜体*`、`` `代码` ``、`~~删除线~~`、`[文字](链接)`、裸链接 `http(s)://`，
以及少量 HTML（`<b> <i> <code> <s> <br>`）的归一。
- 解析不了的一律**原样当普通文字**，绝不吞字符。
- 代码块内部不再二次解析。
- 算式里的 `*`（如 `2 * 3 * 4`）不会被误判成斜体。

### 3.2 Android 渲染（`com.dbpg.duihuazhushou.richtext.RichTextRenderer`）
```kotlin
RichTextRenderer.toSpannable(rich: RichText): CharSequence
RichTextRenderer.applyTo(tv: TextView, rich: RichText)   // 贴文本 + 设排版 + 可长按复制
```
三个诉求的落点：
- **不超框 / 不横滑**：`setHorizontallyScrolling(false)` + `setSingleLine(false)` + `BREAK_STRATEGY_HIGH_QUALITY`，
  并把文本宽度用 `TextView.maxWidth` 封顶（`LinearLayout` 的 `android:maxWidth` 其实不生效，这里改用 TextView 的）。
  长串 / 长 URL 只会在气泡宽度内折行。
- **长按复制**：`setTextIsSelectable(true)`，交给系统选区（长按选词 → 拖手柄 → 菜单「复制」）。
- **顺滑**：见下。

### 3.3 RecyclerView 列表（`com.dbpg.duihuazhushou.chat`）

## 八、会话编辑 / 历史导出 / 生成通道（原生优先）

这一组是"原生持数据、web 只算不发"的核心。

### 8.1 `stcore.session.SessionEditor`

纯函数，无 IO、无 Android 依赖。给定 `SessionDoc` + 操作，返回**新的** `SessionDoc`。

```kotlin
SessionEditor.updateAction(doc, actionId, user = null, ai = null): SessionDoc
SessionEditor.replaceAi(doc, actionId, ai, user = null): SessionDoc
SessionEditor.switchVariant(doc, actionId, index): SessionDoc
SessionEditor.removeAi(doc, actionId): SessionDoc       // 只删 AI，保留用户那句
SessionEditor.removeUser(doc, actionId): SessionDoc
SessionEditor.remove(doc, actionId): SessionDoc         // 整条删
SessionEditor.truncateAfter(doc, actionId): SessionDoc  // 重新生成前砍掉后面
SessionEditor.appendAction(doc, actionId, user, ai): SessionDoc
SessionEditor.upsertImage(doc, actionId, image): SessionDoc
SessionEditor.branch(doc, actionId, newSessionId, newActionId): SessionDoc?
SessionEditor.duplicate(doc, newSessionId, newActionId): SessionDoc
SessionEditor.setDraft(doc, user, ai) / clearDraft(doc)
```

三条语义（与网页 `stores/adventure.ts` 对齐）：

1. `variants[0]` 永远是最新版，`variantIndex` 指向当前显示的那一版；
2. 只有 **AI 正文非空** 的版本才留在 `variants` 里 —— 「‹ ›」只出现在 AI 气泡上，
   切到空版本等于消息凭空消失；
3. 第一次编辑/重生成会先把当前正文存进 `variants`（`seedCurrent`），
   否则初版会被永久覆盖。

### 8.2 `stcore.session.SessionHistory`

```kotlin
SessionHistory.export(doc, uptoActionId = null): List<PromptMessage>
SessionHistory.userInputOf(doc, actionId): String
SessionHistory.lastUserInput(doc): String
SessionHistory.aiTextOf(doc, actionId): String   // 含 [[IMG:]]，给显示/配图用
```

`export` 是**唯一**允许把会话交给外部的地方，它做三件事：

| 规则 | 做法 | 目的 |
| --- | --- | --- |
| 只发当前版本 | 只读 `action.user/ai` | 切了版本不用通知任何人 |
| 图片不进上下文 | `stripImageMarkers()` | 不占 token、不自我强化配图 |
| 空侧不占位 | 空字符串直接跳过 | 不发 `content: ""` 的假轮次 |

`uptoActionId` 用于重新生成：只导出到目标轮**之前**，目标轮的 user 由
`userInputOf` 单独作为"当前输入"发送，避免同一条用户消息出现两次。

### 8.5 引擎设置的边界

`EngineSettingsActivity` 只列出清单 + 勾选，**不读不写预设内容**：

```
__dhpGen.assetCatalog() → { presets, worldBooks, characters, regexGroups, current }
__dhpGen.setActive({"presetId":"..."} | {"worldBookIds":[...]} | {"characterId":"..."})
```

内容始终在 web 的 assets store 里，原生只下"启用哪个"的指令。
这样用户改完网页资产，原生读到的就是同一份，不存在两边分叉。
